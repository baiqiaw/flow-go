# CHANGE — live-qa-acceptance

## Why（为什么做）
在实际项目中，7-验收阶段通过后发布上线仍有明显 BUG。根因是当前验收仅做文档验证（对照 AC 打勾），不实际运行应用、不交互测试、不检查运行时错误。缺少"像真实用户一样使用产品"这一环。

## What（做什么）
借鉴 /qa skill 的方法论，在 7-验收阶段增加 3 个新步骤：
1. 活体验证：启动应用，按用户流程逐页/逐路由测试，收集运行时证据
2. Bug 修复循环：发现的 Critical/High bug 由开发员角色修复，原子提交后重验
3. 验收重验：修复后全量重走核心流程，确认无回归

按项目类型分级处理：Web 应用走浏览器交互，CLI 走命令执行，纯库走测试输出，无法运行则跳过并记录。环境依赖缺失时询问用户是否安装。

修复循环中临时切换到开发员角色，修复完成后切回产品经理角色。与 4-测试的分工：4-测试验证代码正确性，7-验收验证产品可用性。

- 不修改 health_scorer.py 脚本（沿用现有 7 维评分）
- 不引入新的外部依赖或工具（如 Playwright/browse 二进制）
- 不修改归档/同步/进化反思流程

## 验收线
7-acceptance.md 包含活体验证 + 修复循环 + 验收重验 3 个新步骤，UAT.md 模板包含对应字段，闸门规则已更新，SKILL.md 入口/完成条件已更新。
