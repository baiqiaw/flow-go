# Distillation — 输出蒸馏规则

> 借鉴 Kim_Decision 的"反框架展示"理念。阶段完成后对用户可见输出做蒸馏，内部过程保留在工件中供溯源。
> 所有复杂度和路径模式均生效。

---

## 核心原则

1. **工件完整，输出精简**：工件文件（CHANGE.md / DESIGN.md / SUMMARY.md 等）保持完整记录，蒸馏只影响面向用户的终端输出
2. **结论先行**：用户先看到结论和下一步，不需要翻阅过程性信息才能找到行动项
3. **内部记录可溯源**：评审原始评分、自检清单全文、完整推导过程保留在工件中

---

## 蒸馏节奏

阶段完成后，面向用户的输出按此节奏组织：

```
1. 结论     — 一句话：本阶段完成什么、关键决策是什么
2. 关键风险 — ≤3 条，仅保留影响下一步行动的风险
3. 下一步   — 进入下一阶段需要用户做什么（或"自动继续"）
```

以下内容**不在蒸馏输出中展示**（保留在工件文件中）：
- 评审原始评分详情（6 维评分表在 REVIEW.md 中，不在终端输出）
- 自检清单全文（勾选项在工件中，终端只说"自检通过"）
- 重复的上下文信息（上游已传递过的信息不重述）
- 证据标注的完整列表（终端只提关键决策的证据级别）

---

## 反模式

### 反模式：框架倾倒

```
❌ ## 步骤 1 结果
   - 维度 1：充分
   - 维度 2：充分
   - 维度 3：可推断
   ...
   ## 步骤 2 结果
   ...
   ## 步骤 3 结果
   ...
```

### 正确：结论先行

```
✅ 需求分析完成。change-id: user-export，路径：完整。
   关键决策：导出格式选 CSV（非 Excel），理由：零依赖。
   风险：大数据量导出可能超时（>10 万行），验证计划已写入 DESIGN.md。
   → 输入 go 进入设计阶段。
```

---

## 执行位置

蒸馏在以下时机执行：
- 阶段闸门通过后、状态更新前
- 阶段转换时（SKILL.md "第七步 · 状态更新" 之前的蒸馏步骤）

蒸馏不替代工件文件 — 工件仍然是完整的、可交叉评审的。蒸馏只控制用户在对话中看到的内容。

---

## Handoff 中的蒸馏确认

每个 Handoff 的"TO 确认"部分新增一项：
- 确认上游输出的蒸馏摘要与工件一致（摘要与工件冲突时以工件为准）
