# 输出模式压缩规则

> flow-go 4 级输出模式定义。借鉴 caveman 方法论——保留全部技术实质，按需压缩自然语言。

## 模式总览

| 级别 | 名称 | 适用阶段 | 压缩策略 |
|------|------|---------|---------|
| 0 | normal | 6-部署, 7-验收 | 无压缩，完整自然语言 |
| 1 | tight | 0-需求, 1-设计, 2-任务 | 删除礼貌用语/模糊修饰/冗余前缀，保留完整句子 |
| 2 | caveman | 3-开发, 4-测试, 5-审查 | 删除冠词/填充词/寒暄，输出 `[对象] [动作] [原因]。[下一步]。` |
| 3 | ultra | 子代理（探索/审查） | caveman全部 + 删除连接词/省略主语，箭头因果 + 单字表达 |

## 阶段默认映射

| 阶段 | 默认模式 | 说明 |
|------|---------|------|
| 0-需求 | tight | 需求文档详实但去冗余修饰 |
| 1-设计 | tight | 技术决策清晰但去寒暄 |
| 2-任务 | tight | 任务定义精确但去废话 |
| 3-开发 | caveman | 代码级输出，极简形式 |
| 4-测试 | caveman | 测试结果直击要害 |
| 5-审查 | caveman | 审查意见一针见血 |
| 6-部署 | normal | 部署操作不可逆，完整表达 |
| 7-验收 | normal | 验收需完整 AC 对照 |
| 子代理 | ultra | 探索/审查子代理，碎片化输出 |

## normal — 完整表达

不应用任何压缩规则。所有输出保持完整自然语言。

**中文示例**：
> 我已经完成了代码修改，现在需要运行回归测试来验证。有 3 个测试需要执行，预计需要 2 分钟。

**英文示例**：
> I have completed the code changes and now need to run regression tests to verify. There are 3 tests to execute, which should take about 2 minutes.

## tight — 紧凑模式

**删除项**：
- 礼貌用语（请/谢谢/感谢/辛苦了）
- 模糊修饰（可能/大概/好像/差不多/应该可以/也许）
- 冗余前缀（"我认为"/"在我看来"/"据我所知"/"我想说的是"）
- 过度铺垫（"首先让我解释一下"/"在此之前需要说明"）
- 冗长转折（"然而需要注意的是"/"尽管如此仍需指出"）

**保留项**：
- 完整句子结构（主谓宾）
- 技术实质全部保留
- 代码块、错误原文、URL 原封不动

**中文示例**：
> 代码修改完成。运行 3 个回归测试，预计 2 分钟。

**英文示例**：
> Code changes done. Running 3 regression tests. ETA 2 minutes.

## caveman — 穴居人模式

**删除项**（tight 全部 + 以下）：
- 冠词（a/an/the）
- 填充词（uh/um/well/just/actually/basically）
- 寒暄语（hi/hey/hello/good morning）
- 模糊修饰（tight 全部 + 有点/稍微/某种程度上）
- 长同义词（用短的替代长的）

**输出格式**：
```
[对象] [动作] [原因]。
[下一步]。
```

**中文示例**：
> 代码完成。跑 3 测试，2 分钟。
> 然后提交。

**英文示例**：
> Code done. Run 3 tests, 2 min.
> Then commit.

## ultra — 极限模式

**删除项**（caveman 全部 + 以下）：
- 连接词（and/but/or/then/also/so）
- 主语省略（当上下文明确时）
- 介词简化

**输出格式**：箭头因果链 + 单字/双字表达

**中文示例**：
> 代码OK→3测试→2分→提交

**英文示例**：
> code→3test→2min→commit

## 保留项（全级别通用）

以下内容**始终保留原样**，不应用任何压缩：

- **技术术语**：类名、函数名、变量名、API 端点、数据库字段
- **代码块**：``` 包裹的所有内容（含内联代码 `like_this`）
- **错误原文**：错误消息、堆栈跟踪
- **URL 和路径**：所有链接和文件路径
- **数字和单位**：具体数值（3 个文件、2 分钟、500ms）
- **安全警告**：涉及不可逆操作（部署/git push/数据库变更/权限变更）的描述

## 安全自动退出

以下场景自动切回 normal 模式，无论当前压缩级别：

1. **不可逆操作确认**：git push --force / 数据库迁移 / 权限变更 / 删除资源
2. **安全审查步骤**：5-审查阶段的 HARD-GATE 安全审查
3. **部署操作**：6-部署阶段的所有部署命令
4. **用户困惑检测**：当用户连续 2 次提问同一问题，或明确表示"不清楚/不明白"
5. **错误发生**：命令执行失败（exit != 0）时，错误分析使用 normal 模式

操作完成后恢复原压缩级别。
