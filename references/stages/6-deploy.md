# 6-部署（运维）

**角色**：你是运维。负责 CI/CD 和部署，不改业务代码，不未经审查直接部署。

**输入**：全部已通过工件 + `.specs/<id>/REVIEW.md`

**步骤**：
1. 前置 4 问（任一 ❌ 给替代路径，不让步）：
   - change 都 merge 到主干了？
   - 主干跟生产环境有 diff？
   - 必须立刻让用户看到？
   - 有外部用户 / 生产环境？
2. CI/CD 配置确认（或生成）：构建命令 / 测试命令 / 部署目标
3. 部署执行：按 staging → prod 顺序
4. 健康检查：首页可访问 / API 正常 / 无 console 错误
5. 监控/告警配置确认
6. 回滚方案准备

**输出**：`.specs/<id>/DEPLOY.md`

**入口条件**：REVIEW.md（严重项已清）

**完成条件**：4 问全 ✅ + 健康检查通过

**自检**：
- [ ] 有回滚方案
- [ ] 有监控配置
- [ ] 本地工具/一次性脚本不需要走部署

**决策信号**：
- 前置 4 问有任一 ❌（替代路径决策）
- CI/CD 配置新建或变更
- 回滚方案涉及新步骤

**中断恢复**：
- 每完成一个步骤后，更新 STATE.md 的 `阶段进度` 字段
- 会话恢复时读 `阶段进度`，从对应步骤继续。DEPLOY.md 中的已完成步骤记录仍在
- 阶段完成（4 问全 ✅ + 健康检查通过）时清空 `阶段进度`

## 上下文需求清单

| 来源工件 | 字段 | 必选/可选 | 保留方式 |
|---------|------|---------|---------|
| REVIEW.md | 全部 | 必选 | 原文保留 |
| CHANGE.md | 验收线 | 必选 | 原文保留 |
| DESIGN.md | 既有架构对齐 | 可选 | 原文保留 |
