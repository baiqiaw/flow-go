# 工件示例 — REQUIREMENT.md

> 示例：一个"用户登录"功能的 REQUIREMENT.md，展示好工件的标准。

---

```markdown
# REQUIREMENT — user-login

## 用户故事
作为 已注册用户，我想 通过邮箱和密码登录系统，以便 访问我的个人数据和功能

## 验收准则（BDD）
### AC-1 正常登录
**Given**: 用户已注册，邮箱 user@example.com，密码正确
**When**: 在登录页输入邮箱和密码，点击"登录"
**Then**: 跳转到首页，显示用户昵称，顶部导航显示"退出"按钮

### AC-2 密码错误
**Given**: 用户已注册，邮箱 user@example.com
**When**: 输入错误密码，点击"登录"
**Then**: 显示"邮箱或密码错误"，密码框清空，不跳转

### AC-3 账号锁定
**Given**: 用户已注册
**When**: 连续输入错误密码 5 次
**Then**: 账号锁定 30 分钟，显示"账号已锁定，请 30 分钟后重试"

### AC-4 会话过期
**Given**: 用户已登录，会话 24 小时未活动
**When**: 再次操作
**Then**: 跳转到登录页，显示"会话已过期，请重新登录"

## 范围排除（这次不做）
- 不支持第三方 OAuth 登录（Google/GitHub）
- 不支持手机号+验证码登录
- 不支持"记住我"功能

## 非功能需求
- 性能：登录响应 < 500ms（P95）
- 安全：密码不明文传输（HTTPS），失败不泄露用户是否存在
- 兼容：Chrome 90+ / Firefox 88+ / Safari 14+

## 术语表
| 术语 | 含义 |
|------|------|
| 账号锁定 | 连续失败后临时禁止登录的安全机制 |
| P95 | 95% 请求的响应时间 |
```

---

## 好工件特征

- [x] 每条 AC 有 Given/When/Then，可测试
- [x] 覆盖正向（AC-1）+ 错误（AC-2）+ 边界（AC-3）+ 时序（AC-4）
- [x] 有范围排除（≥ 1 条）
- [x] 非功能需求有量化指标（非"要快"）
- [x] 术语表解释非通用概念
- [x] 无实现细节（不提 JWT/Session/Redis）
