# 规格工件模板

> CHANGE.md / REQUIREMENT.md / DESIGN.md / ARCHIVE.md — 0~1 阶段产出。

---

## 交叉评审前自检清单

> 在 dispatch 交叉评审子代理之前，逐项检查。全部通过后才调用子代理（节省 token）。

### CHANGE.md 自检
- [ ] Why/What 有实际内容（非占位符）
- [ ] 影响面所有字段已填写（是/否）
- [ ] 范围排除 ≥ 1 条（非"无"）
- [ ] 验收线可判定（有明确完成标准）
- [ ] 路径建议有理由

### REQUIREMENT.md 自检
- [ ] 无 TBD/TODO/待定 占位符
- [ ] AC 条数 ≥ 1，每条有 Given/When/Then
- [ ] 非功能需求有具体指标（非"待定"）
- [ ] Out of Scope ≥ 1 条
- [ ] Principles ≥ 1 条
- [ ] 术语表有实际条目（如涉及专业术语）
- [ ] 术语表与 .specs/CONTEXT.md 一致（如已存在）

### DESIGN.md 自检
- [ ] 无 TBD/TODO/待定 占位符
- [ ] 技术栈选定有最终选择和理由
- [ ] ADR 每条有替代方案对比
- [ ] ADR 三条件评估已完成（每条 ADR 有三条件判断记录）
- [ ] 风险表有缓解方案
- [ ] 棕地项目：既有架构对齐已填写

## 影响面
- 涉及模块：<列出>
- 数据库变更：是 / 否
- API 变更：是 / 否
- 依赖变更：是 / 否
- CONTEXT 需更新：是 / 否

## 范围排除（这次不做）
- <至少写 1 条>

## 验收线
<简要描述什么时候算做完>

## 路径建议

**Given**: <前置条件>
**When**: <触发动作>
**Then**: <预期结果>

### AC-2 <标题>
...

## 非功能需求
- 性能：<指标>
- 安全：<要求>
- 兼容：<范围>

## Out of Scope（范围排除）
> 列出本次不做的内容，避免需求蔓延。
- <例如：不涉及用户权限系统改造>
- <例如：不考虑离线模式>

| <术语> | <定义> |
