# 记忆工件模板

> ADR / CONTEXT — 跨 change 持久化的决策与术语记录。

---

## 交叉评审前自检清单

> 在 dispatch 交叉评审子代理之前，逐项检查。全部通过后才调用子代理（节省 token）。

### ADR 自检
- [ ] 标题简洁明确（非占位符）
- [ ] 背景说明了决策上下文（非泛泛描述）
- [ ] 选项表格至少 2 个方案（含现状）
- [ ] 决策与选项表格中某一方案对应
- [ ] 理由回答了"为什么选这个"
- [ ] 状态字段已填写（已采纳 / 已废弃 / 已替代）

### CONTEXT 自检
- [ ] 仅包含领域术语（无通用编程概念）
- [ ] 每条术语一条定义（无实现细节）
- [ ] _避免_ 列表有实际别名（非占位符）
- [ ] Relationships 部分关系准确
- [ ] 无 TBD/TODO/待定 占位符

---

## ADR（.specs/adr/NNNN-\<slug\>.md）

### 三条件前置检查

> 以下三个条件 **全部满足** 时才创建 ADR；否则在 DESIGN.md 的 ADR 段落记录即可。

1. **难以逆转** — 撤回成本高或影响范围广
2. **无上下文会困惑** — 未来团队成员不理解"为什么这样做"
3. **有真实方案取舍** — 至少两个可行方案，各有优劣

```markdown
# ADR-NNNN <标题>

## 背景
<描述触发此决策的问题或需求>

## 选项

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A: <名称> | <简要说明> | <...> | <...> |
| B: <名称> | <简要说明> | <...> | <...> |
| C: <名称> | <简要说明> | <...> | <...> |

## 决策
<选择哪个方案，一句话>

## 理由
<为什么选这个方案，2-3 句>

## 状态
- [ ] 已采纳 / 已废弃 / 已替代（替代为 ADR-XXXX）
```

## CONTEXT.md（.specs/CONTEXT.md）

### 规则

> 以下规则确保 CONTEXT.md 保持精炼、可维护。

- **只记领域术语**，不记通用编程概念（如"回调"、"哈希表"）
- **只记定义**，不记实现细节
- **最小化原则**，能从上下文推断的不记
- **一条一句定义**，避免复合句

```markdown
# <项目名> 项目词典

## Language

| 术语 | 定义 | _避免_ |
|------|------|--------|
| <术语A> | <一句话定义> | _避免_ <别名1>、<别名2> |
| <术语B> | <一句话定义> | _避免_ <别名3> |

## Relationships

- <术语A> 是 <术语B> 的 <关系>（如：父/子/同义/反义/依赖）

## Flagged ambiguities

> 标记需要进一步澄清的歧义术语。

- <术语X>：在 <场景1> 中含义为 <...>，在 <场景2> 中含义为 <...>，待统一
```
