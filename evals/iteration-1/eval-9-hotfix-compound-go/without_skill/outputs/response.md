## P 等级判定

**P0（完全不可用）** — 登录是核心入口，白屏意味着用户完全无法使用系统。

按照热修流程：**P0 先回滚再诊断**。

## 2. 根因分析（Iron Law — 无根因不修复）

### 收集症状

- **现象**：输入正确账号密码后页面变成空白（白屏）
- **复现条件**：登录页 → 输入正确凭据 → 点击登录 → 白屏
- **最近变更**：需要查看 `git log` 和 `git diff` 确认最近的代码变更

### 根因假设（最多 3 个）

**假设 1：前端路由跳转失败**
- 登录成功后前端路由跳转到主页/Dashboard，但目标路由组件未正确加载或路由配置有误
- 验证方式：检查浏览器控制台是否有 `Cannot read property of undefined` 或路由相关错误；检查登录后的 `router.push()` 目标路由是否在路由表中注册

**假设 2：认证接口返回数据结构变更**
- 后端登录接口返回的 token 或用户信息字段名/格式发生变化，前端解析失败导致页面渲染崩溃
- 验证方式：检查 Network 面板中登录接口的响应体，对比前端期望的字段名；检查是否有 try-catch 缺失导致未捕获异常

**假设 3：CSS/渲染层面问题**
- 页面内容渲染成功但样式问题导致内容不可见（如 `display: none`、`visibility: hidden`、`opacity: 0`、白色字体白色背景）
- 验证方式：浏览器开发者工具检查 DOM 节点是否存在但不可见；检查最近的 CSS 变更

### 假设验证

**优先验证假设 1（最常见原因）**：

```bash
# 检查路由配置文件
grep -r "router" src/router/ --include="*.ts" --include="*.js" -n
# 检查登录成功后的跳转逻辑
grep -r "login.*success\|afterLogin\|onLoginSuccess\|router.push\|navigate" src/ --include="*.ts" --include="*.js" --include="*.vue" --include="*.jsx" --include="*.tsx" -n
```

**验证假设 2**：

```bash
# 检查登录 API 调用和响应处理
grep -r "login\|auth\|token" src/ --include="*.ts" --include="*.js" --include="*.vue" -n | grep -i "fetch\|axios\|api\|response"
```

**验证假设 3**：

```bash
# 检查最近的 CSS 变更
git diff HEAD~3 -- "*.css" "*.scss" "*.less" "*.vue"
```

### 作用域锁定

根据根因确定相关目录后，限制编辑范围，防止"顺手改了别的"。

---

## 3. 修复方案（待根因确认后）

根据根因假设，可能的修复方案：

### 如果是假设 1（路由跳转失败）
- 检查并修复路由配置
- 确保登录成功后跳转的目标路由已注册
- 添加路由守卫的错误处理

### 如果是假设 2（接口数据结构变更）
- 修复前端对登录响应的解析逻辑，适配新的字段名/格式
- 添加防御性编程（可选链、默认值）
- 后端如需修复则同步调整

### 如果是假设 3（CSS/渲染问题）
- 修复样式规则
- 检查是否有全局样式覆盖导致内容不可见
